PDF Diff - 시스템 아키텍처 (설계도)

이 문서는 클린 아키텍처(Clean Architecture) 원칙에 따라 구성된 PDF Diff 시스템의 구조를 설명합니다. 각 계층은 독립적이며, 의존성 규칙(안쪽 계층은 바깥쪽 계층을 모름)을 따릅니다.

UI 계층 (Presentation Layer)

사용자 인터페이스를 담당합니다. 사용자의 입력을 받아 Application 계층으로 전달하고, 결과를 화면에 표시합니다.

  • main_window.py: 메인 메뉴 창
  • template_editor_window.py: 템플릿 생성 및 편집 창 (ROI 설정 UI)
  • validation_window.py: 문서 검증 도구 창 (결과 비교 및 저장 UI)
↓

응용 계층 (Application Layer)

사용자의 요청을 처리하는 Use Case를 조정합니다. Domain 계층의 서비스와 엔티티를 조합하여 비즈니스 흐름을 제어합니다.

  • main_controller.py: 전체 애플리케이션의 흐름을 제어하는 최상위 컨트롤러
  • template_controller.py: 템플릿 편집 기능의 흐름을 제어
  • validation_controller.py: 문서 검증 기능의 흐름을 제어
↓

도메인 계층 (Domain Layer)

애플리케이션의 핵심 비즈니스 규칙과 데이터를 포함합니다. 다른 계층의 변화에 영향을 받지 않는 순수한 로직입니다.

  • Entities:
    • template.py: 템플릿 데이터 구조
    • roi.py: 관심 영역(ROI) 데이터 구조 및 OCR 설정
  • Services (Interfaces):
    • template_service.py: 템플릿 관련 비즈니스 로직
    • validation_service.py: 문서 검증 관련 비즈니스 로직
    • ocr_service.py: OCR 기능에 대한 인터페이스 (엔진 교체 가능)
  • Repositories (Interfaces):
    • document_repository.py, template_repository.py 등: 데이터 저장소에 대한 인터페이스
↓

인프라 계층 (Infrastructure Layer)

외부 기술(라이브러리, 프레임워크, DB)에 대한 구체적인 구현을 담당합니다. Domain 계층의 인터페이스를 구현합니다.

  • Services (Implementations):
    • anchor_finding_service.py: 자동 앵커 탐색 등 OpenCV 기반 비전 로직
    • validation_vision_service.py: SSIM, Contour 등 이미지 비교 검증 로직
    • tesseract_ocr_service.py: Tesseract 라이브러리를 사용한 OCR 인터페이스 구현체
  • Repositories (Implementations):
    • json_template_repository.py: 템플릿을 JSON 파일로 저장하는 구현체
    • fitz_document_repository.py: PyMuPDF(fitz)를 사용한 PDF 문서 처리 구현체
